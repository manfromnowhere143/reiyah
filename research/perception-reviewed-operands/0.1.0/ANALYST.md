# Common reviewed comparison, 0.1.0

This private folder gives both analysts the same conditional comparison and complete selected
review basis. Preparation performs no human review, stage release or physical acceptance.
Keep it out of discovery review until both independent records have been locked and the
later disclosure has been authorized. No identities or source text have been anonymized.

Select the expected preparation digest from the operator's frozen exchange before reading
results. `PREPARATION.json` binds every file. The `check` command also reconstructs the packet
from separately selected binding, admission request/report and assistance identities.

Read `comparison.json` for the common anchor weights, loss, tolerance, output availability,
model variables/clauses, and each anchor's reference. It is a direct input to
`tools.perception_decision run`. Keep the same joint assignment across every anchor and both
configurations. Optimize the weighted total over allowed assignments; separate anchor extrema
are generally an outer bound, not an exact joint result. Refuse unsupported states explicitly.

Read `admission.json` for the unchanged selected admission report: full discoveries and their
locators, assisted proposals, all adjudication worlds/dispositions and rationale, coverage
assumptions, inspection/timing guards, nominal geometry, generated reference and compilation.
It includes private handles, source IDs and filesystem coordinates. Both methods get identical
bytes; renamed prediction rows are not anonymity or a blindness guarantee.

`renamings.json` maps canonical anchors and every qualified detection to common row identities.
Distinct source rows stay distinct even when their values agree. In a finite reference, graph
object IDs and edge conditions remain unchanged; only edge detection endpoints are renamed.
`world_encodings` maps each original world to its common Boolean assignment. `object_mapping`
links graph IDs to original objects and proposal members. Its scope includes proposed nodes
before an open fallback: an entry does not imply that a finite graph was emitted.

For an object in one world, locate its `reference.worlds[].anchors[].objects[]` entry in the
admission, follow `members` into `proposal_registry`, and inspect each proposal's capture/locator.
The adjudication retains exclusions and unresolved proposals even when no graph object exists.
Use the binding's window mapping and the unchanged assistance to locate the comparison frame
and its nominal transforms. Common source rows, normalizer dispositions and substantive reason
text remain in `operands.json`, `assistance.json` and `SOURCE_READER.md`.

Unknown coverage, uninspected evidence, unresolved geometry/time and unavailable detector
outputs remain distinct. A finite empty reference is possible only under the admission's
explicit closure assumptions; an empty annotation list cannot supply those assumptions.
Exact arithmetic does not establish physical coverage, reviewer identity or independence.

`rules.json` retains the existing normalization and loss conventions. Both analysts may use the
same mathematics and Engine/checker code. Report method, decision, unresolved premises and all
preparation, review, computation, integration and correction effort. Synthetic conformance is
an engineering check; actual review evidence and an external conventional analysis remain
separate requirements.
