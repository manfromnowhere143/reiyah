# Prepare people for the development rehearsal

Guide ID: `reiyah.perception-rehearsal.operator-guide`; version `0.1.0`.

This folder is private coordinator material. `PREPARATION.json` in its parent binds the generated
draft files and exact source request. It certifies preparation only. Do not share the entire
kit with a discovery reviewer: the operator folder contains source mappings and detector inputs.
The analysis folder belongs to the later comparison workflow.

The goal is to learn whether people can use the reference workflow and whether it changes a
supported engineering choice at an acceptable effort. Read `plan.json`. The rehearsal uses the
entire supplied, previously exposed development population. It has no held-out cohort or seed.
Do not change the proposed 60-scene selection, loss or review protocol through this exercise.

Before involving reviewers, resolve and record actual identities, competence, conflicts,
availability, prior exposure, viewing tools and an independent adjudication arrangement in a
copy of `assignments.draft.json`. The two discovery reviews must be independent of one another.
The conventional analyst must be competent and equally informed. Record operator/developer
involvement as part of effort; an internal model rehearsal is not human review. Leave unfilled
roles unassigned. No invitations or assisted disclosures are performed by this preparation tool.
The tool does not verify exposure history. Bind the retained history establishing that these
are existing development windows. Confirm a usable JPEG/PLY viewing workflow and give each
reviewer tested opening instructions before calling the materials ready for actual review.

Give each discovery reviewer only their own `discovery-N` folder and the verified neutral
observation package. Each folder names the same expected package seal and contains the same
capture index and guide, but has a separate unassigned record ID. Supply a private copy of the
effort sheet as needed. Do not mix completed records into the immutable source package.
Verify package bytes at actual delivery with the existing observation verifier. The manifest
and source binding retained at preparation cannot prove later delivery bytes or exposure order.

Retain original submissions and exact file identities. Validate and seal each with
`tools.perception_discovery`; inspect the pair report. Distinct handles and local timestamps
cannot verify actual independence or blinding. Retain the external basis for these facts and
the actual staged delivery history before arranging assisted inspection. Preparation and a
passing pair check are not authorization to release the next phase.

When the required people, source evidence and actual ordering are established, preserve both
discovery records before assisted inspection. Keep assisted proposals explicitly separate. Use
the reviewed-source admission interface to bind them and the adjudication ledger to the exact
comparison/package. Every proposal needs a disposition in every joint world; unknown or
unlisted matchable objects remain explicit. Adjudication must not simply select the Engine's
preferred interpretation. Preserve physical disagreement as an alternative when unresolved.
The later evidence packet must contain the full annotations and anonymized predictions on the
same population, with exact file identities and a private configuration mapping. It has not been
prepared by this tool. The operator binding report is not that packet. Prepare one common
packet and record identical staged deliveries; do not let one method receive extra hints.

Both analysts receive the same sources and assumptions at the same logical stages. They may
inspect originals and use the same mathematics. Record versions and preparation effort. Retain
each conclusion's exact bytes and completion/order evidence before exchanging conclusions.
The included JSON files are editable authoring drafts, not schemas, accepted records or a
mechanism for certifying outcomes. Do not label an output independently locked merely because
a file hash exists. Preserve initial outputs, independent adjudication and all later repairs.

`effort.csv` starts with a header and no measurements. Use one segment per person's activity or
compute job. Supply a participant identifier even if one person fills several roles, and a
work scope of `shared`, `engine` or `conventional`. Categories are preparation, review,
integration, calculation, adjudication and
repair. Stages identify discovery, assisted inspection or comparison; record onboarding too.
Report clock-derived, self-reported and unmeasured time distinctly. Blank numeric fields mean
unmeasured, never zero. Avoid double-counting overlapping segments for one person; parallel
people contribute person-seconds separately. Compute elapsed time is not person time. Shared
preparation stays shared in the account, with any allocation to methods stated explicitly.
Report shared-plus-Engine and shared-plus-conventional totals, as well as actual combined
rehearsal effort without counting the shared work twice. Preserve unmeasured segments separately.

The final rehearsal report is a descriptive record: who could complete which steps, exact
blockers, each initial conclusion, disagreements, adjudicated consequential errors, corrections,
and all effort including missing measurements. If both methods reach equally supported
conclusions and conventional work costs no more, differentiation has not been shown. If neither
can support a choice, report what observation is still required. Do not calculate a p-value,
claim a benchmark record or extrapolate from this one already exposed workflow.
