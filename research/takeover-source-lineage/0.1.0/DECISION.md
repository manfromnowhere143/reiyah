# Move from missing capture history to an explicit measurement channel

Document ID: `reiyah.takeover-source-lineage.decision`. Version: `0.1.0`.
Lifecycle status: `exploratory`. 15 October 2026.

Close the historical repair route for the inspected TD2D simulator refs. Its two
public branches have the same Python blob variants already present in current
main, and the required controller path never appears. Further replay of those
snapshots will not provide the missing implementation. Preserve the complete
500-trial census and its unqualified outcome timing.

The conventional baseline is standard Git object hashing and recursive listing,
with the same metadata as the authored Python auditor. It agrees on 175 objects
and 45 root inventories. This validates the inventory claim within its exact
source scope; it does not authenticate the experiment's capture runtime.

A targeted metadata screen of manD 1.0 is separately recorded in
[next-source.json](next-source.json). It was chosen because the retained TD2D
descriptor identifies it as a takeover dataset with vehicle-state data. This is
a change of source and measurement question, not a replacement outcome for the
closed TD2D comparison. Broad literature ranking or superiority is not claimed.

The next useful experiment requires direct event and vehicle-state records,
explicit timestamp semantics and adequate follow-up. Before opening outcomes,
freeze a bounded sample, the event/clock and missingness checks, extraction scope,
resources and rejection criteria. Preserve native acquisition resolution rather
than treating upsampling as new temporal precision. A takeover request, first
action, transition of automation state, collision and stable recovery are
separate events. Do not relabel one as another.

A source is rejected for the proposed temporal endpoint if required fields cannot
be acquired within terms and bounds, clocks cannot be aligned, event codes are
ambiguous, or observation ends cannot be distinguished from monitored negative
outcomes. Such a result does not invalidate that source for its intended uses.
No readiness modeling or product-value case is admitted by this decision. Gate A
remains operator-unaccepted.

The owner allowance is 5,400 seconds with 1,800 reserved for closeout; all source
work shares the original 60-request/16 MiB/2 MiB-per-response budget and 1,800-second
source phase. The next-source screen uses only the unspent allowance. Earlier
requests, failures and active-effort unknowns are retained rather than reset.
