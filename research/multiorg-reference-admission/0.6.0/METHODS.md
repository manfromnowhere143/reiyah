# Complete the selected cohort under one fixed method

Version 0.6.0 extends the qualified complete-pair adapter to the three remaining images named in the [original selection](../0.2.0/protocol.json). It preserves the first image's closed 0.5.0 record. Each new invocation admits one exact image, with separately pinned source bytes, shapes, full tile roster and input digests. It does not introduce a new detector, threshold, loss, reference procedure or image-selection rule.

The three new private acquisitions are Kaggle dataset `christinabukas/mutliorg`, platform version 6, internal release `MultiOrg_v2`: Macros/Plate_23/image_0, Normal/Plate_31/image_6 and Macros/Plate_23/image_1. Three download attempts completed with final HTTP 200 responses, one redirect each and no retry, retaining 132,782,057 TIFF bytes. Stable source locators, lengths, hashes, access metadata and separate redirect counts appear in the [source ledger](sources.json). Signed delivery locations and payloads remain private. Attribution and CC BY-NC-SA 4.0 dataset terms are inherited from the [source notice](../0.1.0/NOTICE.md); model terms are separate.

The method decision is unchanged from 0.5.0, so this continuation reuses its retained primary sources instead of conducting another method-paper search. The seven retained HTTP responses, totaling 470,462 bytes, and the 58,610-byte installed ONNX Runtime wrapper were rechecked against their recorded digests. This is local source reuse, not a fresh literature review or a claim about the best available method in 2026.

The [ONNX Runtime 1.23.0 Python wrapper](https://github.com/microsoft/onnxruntime/blob/v1.23.0/onnxruntime/python/onnxruntime_inference_collection.py) can retry session creation and execution after provider failures. The frozen runner preserves both guards: `enable_fallback=False` during construction and `disable_fallback()` before running. Qualification exercises these Python paths with mocks; it does not establish that earlier empirical attempts retried. The CPU provider, thread counts, execution settings and exact named-output requests remain fixed. The retained [optimization documentation](https://onnxruntime.ai/docs/performance/model-optimizations/graph-optimizations.html) does not promise bitwise equivalence after changing graphs, fetches or execution providers; no such substitution is made.

The reused [SAHI source at commit 80ebdb699851facf87def03c0597e1aeb87a9a2d](https://github.com/obss/sahi/tree/80ebdb699851facf87def03c0597e1aeb87a9a2d) offers different experimental choices. Its sliced predictor defaults to greedy merging with intersection over smaller area and an additional full-image prediction. Its edge-window placement and optional buffered merging also differ from the declared lattice and final global IoU-NMS. These alternatives were inspected for compatibility in 0.5.0; they were not executed or compared here. Adopting them during cohort completion would change the question after exposure.

The corrected Faster observation graph remains a distinct variant. Every tile retains all 33 declared arrays and undergoes the same origin/selection checks; YOLO remains unchanged. The original preprocessing, float32 analysis threshold strictly above 0.5, coordinate conversion, flooring, row identities, tie policy and whole-image hard NMS are preserved. Low-score bookkeeping rows remain recorded. Missing or failed tiles cannot become empty detections, and no original-model counterfactual is inferred from corrected arrays.

Each image has 156 tiles per model. Its array budget is derived from static output caps: 59,945,184 bytes for Faster and 6,877,952 for YOLO, totaling 66,823,136 bytes including conservative NPY headers. The capture ceiling is 128 MiB per pair, distinct from the 64 MiB per-file ceiling and 3 GiB sampled-RSS supervision. Each new pair has a 600-second limit; the new owner authorizes at most 1,800 seconds across the three pairs, in their original order. This is an explicit continuation budget. Previous failed attempts, acquisition and engineering effort remain part of the history and are not reset.

The full comparison requires all four complete image pairs and all twelve fixed reference cases under a separately frozen empirical matching input contract. A null or unresolved composition contrast is retained. Completion does not establish physical truth, general model preference, automotive transfer, independent replication or an advantage in complete human work. Required software attribution remains unchanged in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
