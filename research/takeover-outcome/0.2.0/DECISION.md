# Complete the source census; retain the temporal boundary

Document ID: `reiyah.takeover-outcome.decision`. Version: `0.2.0`.
Status: `exploratory`. 15 October 2026.

The decision is whether TD2D's released trial summaries can support a temporally
defined recovery target before readiness modeling. The summaries support a
recorded outcome census and exact differences between recorded timestamps.
They do not currently qualify a common monitored recovery interval. Keep the
readiness model unadmitted and Gate A operator-unaccepted.

The [protocol](protocol.json) preserves the original within-driver/event
comparison. A separately reported projection admits the five uniquely named
required fields without consuming an inconsistent workload suffix. The author
notebook selects these named outcome fields; the original strict-header
admission remains visible in [legacy-result.json](legacy-result.json). This
change was frozen before parsing the 339 newly acquired summaries. The prior
161 summaries and five discordant pairs were already exposed. This is an
exploratory continuation, not a new preregistered or blinded experiment.

## Alternatives and falsification

A direct conventional census and SQL self-join receive the same observations,
field contract and decimal correction as the sorted-list producer. They check
all strata and every discordant witness. There is no complete-work advantage
claim. Dropping the malformed row remains available as a sensitivity comparison;
guessing its workload values is unnecessary. Modeling latency as readiness would
use a measurement taken after the critical event and leave the outcome horizon
unresolved. Searching for a more complex model cannot supply missing timestamps.

The coverage milestone requires all 500 frozen roster members to have checked
source bytes; the essential-field census also requires all five cells to pass
both mappings and temporal arithmetic. Table 4 is a source reconciliation,
not independent scientific validation. Any mismatch is reported. Timing
qualification requires the release's capture/export implementation, clock
mapping, event detection, monitored follow-up and censoring to be established.
A positive duration alone cannot meet that requirement.

The [authored counterexample](timing-counterexample.json) holds the released
fields constant while changing the unobserved failure time from before to after
the first action. It is an information-sufficiency demonstration, not a simulated
or observed crash. It shows why scenario end cannot simply become failure time.

## Evidence needed to reopen temporal qualification

A useful additional packet would link each trial to a versioned capture and
export configuration, specify the clock origin/units and first-maneuver rule,
and provide collision/sidewalk event times or an explicit continuously monitored
interval with its termination reason. Successful trials need the observation end
and censoring status; an absent failure timestamp alone is not success. A shared
recovery horizon must be defined and justified before labels are built.

Start any continuation by checking whether such a materially new public artifact
exists or has been provided. Bind it to the existing release and test whether it
resolves these specific gaps. Stop if it does not. Keep this completed source
census closed; do not reacquire the same summaries, rerun exposed contrasts or
add physiology/eye-video features to compensate. No outreach is authorized by
this packet. If a different source is proposed, record a new measurement question,
exposure, terms and bounded protocol before analysis.

## Resources and boundaries

The frozen owner budget is 7,200 seconds with 1,800 reserved for checking and
closeout; source capture allows 420 requests and 16 MiB, sequentially paced at
least 2.5 seconds apart. Captured earlier bytes and all prior failures/costs are
preserved. Current requests, retained bytes, execution time and unknown costs are
reported in [custody](source-custody.json) and [provenance](provenance.json).

The result is descriptive of this finite simulator dataset. It does not establish
causality, physical recovery, road transfer, latent readiness, a population risk,
scientific superiority or a product-value case. The broader HARBOR mission and
closed microscopy comparison remain intact. No training, inference, deployment,
private participant ingestion or Gate A acceptance is part of this step.
