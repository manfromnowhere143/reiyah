# A takeover deadline is not a recovery horizon

Document ID: `reiyah.mand-semantics`. Version: `0.1.0`.
Lifecycle status: `exploratory`. 16 October 2026.

**Close the inspected manD documentation route without admitting recovery labels.**
The sources clarify a planned nonresponse/termination path and a mode-deactivation
endpoint. They do not supply an executable, release-bound accident monitor, its
latency, a common monitored recovery horizon or an identified positive ego-accident
control. Another unselected participant archive would not repair that dependency.
The [previous recorded-axis result](../../mand-timing/0.1.0/README.md) remains intact.

## What the sources clarify

The [dataset descriptor](https://doi.org/10.1038/s41597-024-03137-y) specifies a
maximum ten-second takeover-request budget and an accident/scenario-end path after
nonresponse. Its code-availability section points to a processing/extraction script.
These statements describe experimental design; they do not establish how each
released accident code was generated or how all other terminations were recorded.

The author's [2025 dissertation](https://doi.org/10.17877/DE290R-25668) describes
that accident as simulated. It defines reaction time from the request to automation
deactivation, which can follow steering, pedals or a button. It also documents
time, technical and behavior-dependent gaps in planned takeover coverage. Its
simulator preparation describes 20 Hz acquisition, 256 Hz delivery and later
16 Hz downsampling for modeling. That later analysis rate is distinct from the
released data. These are source descriptions, not independent clock calibration.

The practical distinction is consequential: a request deadline, an automation
transition, an ego-collision event and a successful recovery are different targets.
A fixed deadline does not establish a fixed observation horizon after intervention.
No P1/anger arithmetic is rerun or relabeled as physical reaction time. The
[findings ledger](findings.json) binds six reviewed passages by exact byte span;
its interpretations remain investigator judgments rather than machine-proved facts.

## What is actually released in the inspected scope

The current Dataverse response is byte-identical to the retained release metadata:
manD 1.0, repository version 2.0, published 24 January 2024. Its 56 listed files
contain 50 participant archives, one EEG-BIDS archive, four workbooks and one
Python script. All are marked unrestricted in that metadata. This is an inventory
of the release listing, not of every archive member or all possible private code.

The exact `DataExtraction.py` matches its advertised size and MD5. Source/AST
inspection finds six functions: two for heart-rate extraction, two for pressure
visualizations and two for nested archive extraction. No field/event-monitor path
is supplied by those functions. Keyword counts are retained only as supporting
inventory; absence of a word alone is not a semantic proof. The code was neither
imported nor executed, and no physiological or media data were opened.

The inspected descriptor, official pages, release metadata, designated script and
dissertation text do not identify a participant/scenario positive ego-accident
control. This is a scoped discovery result, not proof that the dataset has no
accidents, that its labels are wrong or that its original experiment was broken.
The control population remains **unmeasured**, not zero.

## Reproduce the source checks

Use the exact separately obtained files named in [inputs.json](inputs.json), under
their source terms. The repository does not redistribute their bodies. Retained
execution used Python 3.14.2; parser warning counts can be runtime-dependent.
Use a fresh output directory, and do not execute the upstream extraction script:

```sh
reiyah_study=research/mand-semantics/0.1.0
reiyah_sources=/absolute/path/to/qualified-source-files
reiyah_run=/absolute/path/to/new-run
mkdir "$reiyah_run"
python3 -B "$reiyah_study/audit.py" --sources "$reiyah_sources" \
  --inputs "$reiyah_study/inputs.json" --findings "$reiyah_study/findings.json" \
  --output "$reiyah_run/audit.json"
python3 -B "$reiyah_study/verify.py" --sources "$reiyah_sources" \
  --inputs "$reiyah_study/inputs.json" --findings "$reiyah_study/findings.json" \
  --result "$reiyah_run/audit.json" --output "$reiyah_run/verification.json"
python3 -B "$reiyah_study/controls.py" --sources "$reiyah_sources" \
  --inputs "$reiyah_study/inputs.json" --findings "$reiyah_study/findings.json" \
  > "$reiyah_run/controls.json"
```
